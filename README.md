# Домашнее задание к занятию «Резервное копирование баз данных»

## Задание 1. Резервное копирование

### 1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день

**Решение:** полное резервное копирование (Full Backup) ежедневно.  
Почему: одна полная копия содержит все данные, восстановление быстрое и надёжное.  
Альтернатива: дифференциальное копирование (полная раз в неделю + ежедневные дифф. копии) — экономит место и время.

### 1.2. Необходимо восстанавливать данные за час до предполагаемой поломки

**Решение:** инкрементное резервное копирование с частотой раз в час + Point-in-Time Recovery (PITR).  
Как работает: сохраняются только изменения с момента последней копии. Для PITR в PostgreSQL используются WAL-журналы, в MySQL — бинарные логи.  
Рекомендуемая стратегия: полный бэкап раз в сутки + инкрементные каждый час.

### 1.3. Возможен ли кейс моментального переключения на работающую БД?

**Да, возможен.** Используются:
- Репликация (Master-Slave / Primary-Replica)
- Автоматический failover (кластеры высокой доступности: Patroni для PostgreSQL, AlwaysOn для SQL Server)
- Распределённые СУБД (Cassandra, CockroachDB)

**Важно:** репликация не заменяет резервное копирование — при логической ошибке (DROP TABLE) она скопирует и её.

## Задание 2. PostgreSQL

### 2.1. Примеры команд резервирования и восстановления

**Резервное копирование (pg_dump):**
```bash
# Текстовый дамп (SQL-скрипт)
pg_dump -U postgres -d имя_бд > backup.sql

# Сжатый пользовательский формат (рекомендуется)
pg_dump -U postgres -Fc имя_бд -f backup.dump

# Сжатие gzip на лету
pg_dump имя_бд | gzip > backup.sql.gz
```
### 2.2. Возможно ли автоматизировать процесс?
Да. Пример автоматизации через cron (Linux):  
```bash
0 2 * * * pg_dump -U postgres -Fc prod_db > /backups/prod_db_$(date +\%Y\%m\%d).dump
```
Или через небольшой скрипт
```bash
#!/bin/bash
BACKUP_DIR="/backups"
DATE=$(date +\%Y\%m\%d_\%H\%M\%S)
pg_dump -U postgres -Fc mydb > "$BACKUP_DIR/mydb_$DATE.dump"
find "$BACKUP_DIR" -name "*.dump" -mtime +30 -delete
```
Также существуют специализированные инструменты: pg_basebackup, pgBackRest, barman.

## Задание 3. MySQL    
### 3.1. Пример команды инкрементного резервного копирования
```bash
mysqlbackup --user=bkpuser --password=s3cret --backup-dir=/backups \
            --incremental --incremental-base=dir:/backups/full_backup backup
```
### 3.2. Преимущества реплики по сравнению с обычным бэкапо
| Преимущество  | Описание |
| ------------- | ------------- |
| «Живая» копия  | Реплика готова заменить master при отказе (failover)  |
| Безопасный бэкап  | Можно делать бэкап на реплике — без нагрузки на master  |
| Масштабирование чтения | Запросы SELECT распределяются между репликами |
| Аналитика и отчёты  | Тяжёлые отчёты выполняются на реплике, не мешая операционной работе  |
| Геораспределение | Локальная копия для удалённого офиса |
